3. 自動照合できない配布チャネル（AIヒント方式で対応）

以下のような配布チャネルには専用の自動照会アダプタがありません。製品がこれらに該当する場合、 Claude APIキー登録済みであればTier3のWeb検索がベンダー名の特定を試み、識別子が判明すれば 「ヒント」として結果画面に表示し、その識別子を使った簡易的なAI脆弱性調査（Stage4）も行います。 ただし自動レジストリ照合のような確度の高い検証はできません。

  • VS Code Marketplace（拡張機能）
  • Chrome ウェブストア（拡張機能）
  • Docker Hub（コンテナイメージ）
  • Homebrew（macOS/Linuxパッケージ）
  • Linuxディストリビューションの各パッケージマネージャ（apt/rpm等）
  • 各種App Store / モバイルアプリストア

このリストは固定の実装ではなく、AIが都度自由記述で判断するため網羅的ではありません。 上記以外のチャネルでもAIが識別子を認識できればヒントとして表示されます。

4. ベンダー公式アドバイザリー（CSAF等）

Siemens ProductCERT・Red Hat Product Securityが公開するCSAF形式のセキュリティアドバイザリーは、既知のCVEに 対してベンダー独自の適用可否ステータス（修正済み／影響あり／影響なし／調査中）を注記として表示します（他の 情報源が該当CVEを見つけた場合のみ表示——CSAF単独でしか見つからないCVEについては、修正済み・影響ありの場合の み新規に表示します）。Ciscoについては専用アダプタが未実装です（システムレベル認証情報が必要なため）。該当 する脆弱性はStage4のAI Web検索が見つけられる場合があります。
